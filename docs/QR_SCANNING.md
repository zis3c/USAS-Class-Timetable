# QR Scanning

## Where it is used

The shared decoder in `src/shared/lib/qrDecode.ts` powers both:

- Schedule sharing and comparison in `CompareScheduleModal`.
- Lecturer attendance codes in `AttendanceScanModal`.

Both screens keep their own camera and result handling. The decoder reads camera frames or selected images locally in the browser. Image files and QR payloads are not uploaded by the scanner. Attendance sends only the decoded text to the existing USAS API flow.

## Decoder and camera flow

The project uses [`qr-scanner`](https://github.com/nimiq/qr-scanner) with a shared Web Worker on all browsers. This keeps inverted-code support consistent instead of relying on each browser's native `BarcodeDetector` behavior. The shared engine is reused so camera scans do not create a new worker on every frame.

Camera callers pass a video element and a reusable canvas to `decodeQrFromFrame`. The decoder downsizes the full frame for a quick pass. Every fifth pass scans a centered crop for more detail. The crop follows the current digital zoom. A decode miss returns `null`; the caller keeps scanning.

The worker is configured for both dark-on-light and light-on-dark codes. This matters for QR images generated by the app in dark theme. The worker message used for this setting follows `qr-scanner`'s worker protocol, so recheck it whenever that dependency is upgraded.

## Image uploads

Callers load a selected image and pass it to `decodeQrFromImage`. The decoder tries the complete image and a centered crop at up to 1,200 and 2,000 pixels on the longest side. It then tries a JPEG softened center crop to reduce screen moire. This limits canvas memory use on phones while retaining a higher-resolution pass for dense codes.

The file input accepts `image/*` so mobile photo pickers can offer their available image formats. Object URL lifetime and input reset stay with each modal's upload handler.

## Browser and deployment requirements

- Camera access needs HTTPS, except on localhost, and user permission.
- Keep the camera video muted and `playsInline` for inline playback in iOS Safari.
- Keep `worker-src 'self' blob:` in `public/_headers`. The library creates its fallback worker from a blob URL.
- Deploy the Vite output in `dist` as a whole. Vite emits the scanner worker as a separate asset.
- Upload scans run locally and need no network access. Attendance sends the decoded QR text through its existing API request after decoding.

## Debugging

Open Attendance with `?qrdebug=1` to show camera dimensions, canvas dimensions, average frame brightness, decode time, and scan count in the status area. The readout does not include the QR payload. Compare Schedule does not currently show this diagnostic panel.

If a browser cannot read a code, first check camera permission and HTTPS, then confirm the code is inside the centered scan guide and in focus. For deployed failures, check that the scanner worker asset returns successfully and that the site's Content Security Policy still allows it.

## Device validation

- iPhone XS camera scan: confirmed working by the user after enabling both QR color modes.
- Android Tab A8 camera scan: previously confirmed working, though movement was needed to bring the code into focus.
- Desktop camera behavior has not been confirmed on physical hardware. Camera choice, focus, and browser permissions vary by device.
